## 目标

规划与行动现在独立限额：`--planning-output-tokens 2400`（默认）用于自然语言拆解，`--max-output-tokens` 继续约束后续调用。格式/截断恢复切换 core 形状，最多1600输出 Token，不自动放大原总预算。不要再单靠提高所有节点的输出长度绕过规划结构过重的问题。两种阶段仍计入同一 calls/tokens/estimated cost；临时阶段限额不会改动共享 Provider 或漏算失败请求。

2026-10-28《王座厅的最后一夜》重测：规划一次成功，867 input / 645 output，按既定价格假设估算0.003447美元；此前两次截断共0.016252美元。后续模拟仍失败：四条行动没有完成结尾，15请求后在下一次发送前触及剩余预算保护，当前0.075305美元；合计17请求、0.091557美元，没有新增评委/重跑/文学成稿。规划修复得到本样本验证，不等于角色自主性、状态语义或叙事质量通过。最新单份 Markdown 保留手工评审，历史失败不改写为成功。

Eval 使用固定场景和当前已配置的模型，检查模拟效果是否随代码、提示词或模型调整而提升。它与 `pytest` 完全隔离，普通测试和启动 AUV 都不会触发付费调用。

普通 pytest 另外使用真实执行器跑 24 轮 / 72 个假模型行动，验证状态持久性、私有范围、无效来源拒绝和审计链，不访问供应商。既有 60 步 sparse checkpoint 评测也不是 60 轮真实模型执行；探针错误/缺失保留为真实失败或未完成证据，不能当作 simulated 通过。

## 固定文风基准

`writing_styles` 使用同一段固定的还书场景素材，分别生成小说和剧本。不重跑模拟，避免把剧情随机性误认为文风变化；每份作品正常生成及忠实度核验各一次，发现问题最多修正及复核各一次。两份作品正常四次调用，再可选一次共同文风评分。

写作要求与评分标准保存在 `backend/evals/styles.json`，各自带版本：

- `novel`：第三人称限知、克制现实主义小说；检查稳定视角、自然段、对白与选择性心理描写、潜台词。
- `screenplay`：简洁写实剧本；检查场景标题、可拍摄动作、人物对白、可表演的节奏；不要求小说式心理描写。
- 共同三项：事实忠实度、可读性、无冗余。丰富细节可以得高分，短文本不会自动得高分。
- 每种体裁另有形式、文风两项；共五项各 0-4 分：缺失、严重不符、好坏参半、基本符合、充分符合。代码求和乘 5，分别得到 100 分制结果，不把两种体裁混成一个排名。
- 模型必须给出五项有效整数分数；缺项、重复或格式错误显示不可用，不补分或当作通过。

```powershell
cd backend
python -m app.eval_runner --scenario writing_styles --judge --max-calls 5 --max-output-tokens 900 --max-total-tokens 12000 --max-cost-usd 0.05
python -m app.eval_runner --scenario writing_styles --execute --judge --max-calls 5 --max-output-tokens 900 --max-total-tokens 12000 --max-cost-usd 0.05
```

只测试一种形式时添加 `--style novel` 或 `--style screenplay`。也可以在普通模拟评测中添加这些选项，先运行真实模拟，再生成指定形式；每种形式正常额外两次逻辑调用，发生修正最多四次。上述五次预算不预留全部修正或传输重试，额度不足会停止，不自动扩容；可先预检再自行决定上限。用户在产品中仍可自由填写文风，不受此处基准限制。提示词与核验契约版本已提升至 3，避免与旧的无核验基准混比。

固定素材、写作要求、评分标准和评审模型一致时，记录才显示上次同配置的分差；内容指纹和版本避免修改标准后仍比较旧分数。若修改评审提示词的评分含义，应提升 `PROMPT_VERSION`。更换模型同时更换了当前评审模型，不直接比较旧分差。

写作基准将流程完整性与文学质量分开记录，命令行只显示各形式质量分，不把生成成功显示为文学质量 100 分。质量看 `Review` 中每种形式的五项得分和最多两条问题。普通模拟的 `Rule score` 也不能代表文学质量。模型评分仍有波动，固定标准不是文学质量保证；显著变化需要人工读正文，必要时用户授权重复试验，而不是默认多跑付费调用。

## Dynamic State 专项

State Coder 的正常提案仍复用 Director 审计。只在结构或操作校验失败时允许一次补编码，Eval 将它统计为 `usage_by_kind.state_repair`，同样计入原有调用、Token、估算费用和物理重试限制，不自动续预算。缺少 state_patch 不是无更新，测试假模型也必须显式返回两个空数组。待编码增量完整进入 Checker，积压可能增加输入 Token，因此不承诺单次费用保持不变或上下文必然缩短。

普通回归新增编码游标、整批提交、空提案确认、私有索引和回滚恢复断言；其中角色移动/归属/死亡等示例若使用人工编写 Patch 或假 checker，只验证工程数据路径，不证明实际模型能正确抽取移动、判断物品转移授权或识别虚假陈述。真实语义完成率、误拒绝率与 Token 对比仍需用户单独授权的小规模实际测试。本次未执行收费请求，也未重评历史失败样本。

`dynamic_state_quality` 使用一段包含对白、动作和短暂心理细节的固定关系冲突，验证模型是否只保留会约束后续行动的事实。规则评分检查：

- 至少捕获一项持久事实，但活动概念不超过四项。
- 每个状态引用准确的节点、行动序号和事件序号。
- 状态值标记为 recorded，区分 claim/observation/action/inference；来源存在或 confidence=1 不等于独立证实，类别含义仍需实际样本人工检查。
- 私有状态只能由其 owner 的行动建立。
- 不把皱眉、叹气、目光、心跳、语气等瞬时叙事细节写入状态。

预检与真实执行：

```powershell
cd backend
python -m app.eval_runner --scenario dynamic_state_quality
python -m app.eval_runner --scenario dynamic_state_quality --execute --judge
```

该场景原预计约 9 次产品调用；当前最多四条行动另增四次一致性检查，`--judge` 再增加一次评审调用，仍受统一调用、Token 和估算费用上限约束。

## 行动一致性检查预算与证据

检查输入现在按稳定证据、当前状态/历史、实际角色输入、候选行动组织，原文只做精确引用去重，不删除未激活的规则或他人私有审计约束。已有各类检查和调用上限不变。`diagnostics.action_check_context` 汇总各块字符/Token估算、未投影基准和供应商返回用量；`Action Checks` 仅增加一行估算说明。两侧使用同一当前检查规则，不能据此认定相对旧版本的总账单降低；缓存是否命中以供应商数据为准。

`diagnostics.round_audits` 保留每个边界的轮号、继续/转场/停止、目标完成标记、内容停滞计数、目标停滞计数和缺失目标判断，不只剩最后两次审计。`goal_progress` 根据实际接纳行动衡量当前退出条件的距离，与有新内容分开；连续2/4/6轮 none/regressed 产生逐级场景反馈，但不强制角色决定或编造完成。缺失或 uncertain 不当作已完成验收；启用 require_scene_control 的规则评分新增目标判断覆盖检查。下一次真实测试应对照逐轮记录与实际行动人工判定，而不是只看分数或计数。

本轮仅完成离线回归，不重新运行王座厅、不调用 Judge、不增加预算。40%-60%输入节省及预算内完结率提升仍是待检验目标，不是当前结果；引用压缩在语义上的可靠性仍需有界真实样本验证。

连续模拟现在逐候选进行接纳前检查。预检会在场景原估算上加行动上限对应的检查次数；一次内置节点修正可另增两次调用。硬上限不会自动放宽，调用额度不足时 `--execute` 会在运行前拒绝；不带 `--execute` 仍只显示预检与预算不足提示。默认 roleplay_basic 的 12 次额度不足当前估算，需要显式设置至少 14 次，或改用更小的场景。原有 Token/费用上限保持不变，所以增加调用额度不保证完整跑完。

当前每个候选会把实际约束交给检查模型，成本高于此前仅做阶段审计。最新 Markdown 仍只保存一份；`Action Checks` 简要列出检查次数与未接纳候选，明确它们不曾成为有效模拟行动，不复制完整检查上下文或 raw Provider 数据。语义误判、对真实矛盾的识别率、自然语言秘密泄露和长程质量仍需人工读实际样本；普通离线测试只证明拒绝/修正/传播隔离等工程路径，不证明模型检查准确。

行动结构门与流程评分共用 ParticipantAction：participation/action 必需，act 非空，wait/observe 可空，不能以缺少私有 intent 作为协议失败。坏 JSON/错误字段/截断回复在语义检查前拒绝；内置格式重生成与语义修正共享候选上限，外接任务不重执行。结构校验本身不增加模型请求，可能的重生成仍受原预算限制。离线假 checker 接受只用于证明合法结构如何继续，不能将它解释为对谎言、角色越权或事实分类的模型准确率。

本次实现未执行新的真实模型调用。历史真实样本发生在接纳门加入之前，不作为本机制的语义验收证据。

## 结果文件

普通 Eval 每个场景只维护一个 `backend/evals/results/{场景名}.md`，再次执行覆盖该场景的最新记录：

精简元数据另含 `completion` 和 `diagnostics`：模型用途归类的调用/Token/失败预留统计、初始阶段/坐标、最近两次 Director 完成判断与场景控制。分类依据现有系统提示词，无匹配归 other，不保存提示词或原始模型响应，不等于供应商账单分类。可以据此区分规划、角色、检查与审计的成本；旧记录不能追补这些缺失证据。

- 正文保存一次：固定素材与各形式成稿，或实际角色行动与结局。
- 附简短评语、失败项、调用次数和估算费用，不保存提示词、原始 Provider 数据或重复全量日志。
- 文件首行包含精简的比较元数据，供下次读取；不再另外生成 JSON 文件。旧版历史产物不自动删除。

上一次结果只是参考，不自动认定为最佳基准。写作基准只对匹配配置显示分差，不自动据此认定提升或退化。产品内的 Full Log、Trace 和 Replay 不受此次评测文件简化影响；长程专项评测仍遵循其独立文档。
