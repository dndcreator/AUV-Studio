# 长程依赖评测

最后更新：2026-10-02

该评测用于检查 World Book、节点私有信息、角色记忆和分布式参与在长时间线中的稳定性。它与普通测试和产品运行完全隔离，不会自动执行。

## 预检

```powershell
cd backend
python -m app.long_horizon_eval
```

预检不生成结果，也不调用模型。

## 零成本模拟

```powershell
python -m app.long_horizon_eval --simulate
```

模拟构建 60 轮时间线，在第 20、40、60 轮检查：

- 全局 World Book 规则是否持续可用。
- 关键词条目是否只在相关场景激活。
- 条目是否因过宽语义词在无关场景被错误激活。
- 私有条目是否只对指定节点可见。
- 第 1 轮写入的承诺是否在第 60 轮仍可召回。
- 群体和个人节点是否获得隔离后的上下文。
- 模型是否真正作出角色行为，而不是把检查问题原样当作决定复述。
- 检查点上下文是否保持在预算内。

该模式只验证工程机制，不证明真实模型会合理使用上下文。

## 真实模型检查点

```powershell
python -m app.long_horizon_eval --execute
```

真实模式不会逐轮调用模型。它先在本地构建完整时间线，只在四个固定检查点调用当前配置的模型，验证模型是否真正使用早期承诺、当前状态和可见 World Book，同时检测私有信息泄漏。

默认硬限制：

- 最多 4 次调用。
- 最多 16,000 Token。
- 单次最多 500 输出 Token。
- 估算费用最多 0.08 美元。
- Provider 自动重试关闭。

CLI 安全上限为 8 次调用、40,000 Token、单次 1,000 输出 Token和 0.25 美元估算费用。费用按参数中的价格假设计算，不等同于供应商账单硬限额。

## 结果

结果写入本地 `backend/evals/results/long_horizon/`，不会进入 Git：

- JSON 保存预算、检查点上下文统计、规则结果和模型响应。
- Markdown 提供失败项、各检查点结果和人工复核清单。

自动规则只能判断事实保留、可见性、关键词命中和泄漏。角色行为是否自然、早期事实是否真正影响决策、长期叙事是否稳定，仍由人工复核判断。
