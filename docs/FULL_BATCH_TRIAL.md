# 真实引擎Batch小场景验收

## 范围与实现

2026-11-11用户批准一次关闭Thinking的真实全链路测试：最多24次请求、8万Token、估算USD0.15，规划首次请求前开始60秒硬截止，取消后保存已发生过程，不补跑、不追加成稿。

原来的Batch只存在隔离评测。现将联合检查规则/解析移到`execution/batch_admission.py`，隔离脚本与引擎共用同一实现。`WorkflowEngine(..., experimental_batch=True)`显式开启实验路径，默认关闭，不新增前端开关。

轮初使用原有角色投影、记忆筛选、背景、Scene Contract和通信上下文冻结输入，并发生成内置自主Agent候选，联合检查后逐项提交到原有事件链、NodeRun和Memory流程。未接纳候选不进入成功事件和记忆。Director/State Coder继续在真实阶段边界联合审计，保留原有来源验证、编码修复、回滚快照和完成判断。不把模型输出直接当权威世界事实。

仅支持内置自主Agent，不支持外接Agent、玩家控制或待处理玩家行动；这些组合明确拒绝，不并发未知副作用。批次进行中的玩家输入/Director覆盖不混入已冻结输入，延后至边界/后续轮次处理；停机仍在提交前检查。模型请求期间不并发使用SQLite Session，最终事件提交有稳定顺序。候选已生成后才建立逐节点执行记录，其节点事件时间不等于生成起点；本次性能诊断以请求trace为准。此实验尚未作为成熟生产调度发布。

执行入口：

```powershell
cd D:\产品\AUV\backend
..\.venv\Scripts\python.exe -m app.evaluation.full_batch_trial
# 明确批准预算后才追加 --execute
```

默认预检零请求。真实执行复用保存的模型配置但只在本次Provider上关闭Thinking，不写回设置。临时SQLite运行编译后的真实WorkflowEngine，保留事件、阶段审计、实际状态检查点、记忆数量及物理请求元数据；不模拟Queue/UI、人类干预、外接工具、独立Judge或额外文学改写。超时等待取消完成后将测试Run置为stopped，不留运行孤儿。

## 实测：2026-11-11 23:54北京时间开始

场景：信使玛拉最初主张走南门，伊文知道南门已封锁、北门可通；二人交流后各自决定是否同意改道。最多3轮/6行动，模型实际规划和路由，不强制导演替角色同意。

**按60秒产品目标，本次未通过。** 计时60.132秒，132ms为截止后取消/本地收尾附近的开销，没有继续模型请求。取消了第3轮Actor请求，不补跑。12次物理请求、36294输入/5007输出Token，估算USD0.056322；取消请求含输入估计及2400输出预留，不能当供应商实际账单或Thinking耗尽证据。

| Semantic Router | 3次，共13.632s；首轮选2人，第二轮只选玛拉 |

首批公开行动约在规划起24.9秒后接纳，是后端请求终点近似，不是前端首帧。Actor所有请求耗时相加18.675秒，但首轮存在重叠，不可全加到墙钟。规划、路由、联合检查、边界审计仍有明显串行等待。此单样本不能估计稳定p95或硬件/供应商普遍速度。

## 两个核心问题的判断

1. **Batch接入能否工作：有限通过。** 首轮两个冻结输入的角色确实并发提案，一次联合检查后进入真实事件、记忆与状态编码；没有观察到替对方决定或提前回应同轮话语。但仅一个双候选批次，不证明一般并发语义正确、冲突裁决成熟或长程稳定。
2. **故事能否持续进展：有证据，但未收束。** 玛拉提出南门，伊文提供新信息，下一轮玛拉明确改走北门。不是完全空转；但60秒仍未结束，不能把有进展称为产品目标通过。

额外发现：

- Director第二次认为伊文尚未明确同意，要求再激活伊文；实际上他第一轮已说“咱们改走北门吧”。这是疑似过度确认/语义收敛误判，产生了额外路由与Actor等待；未使用独立Judge，不报虚假的准确率。
- State Coder将`south_gate_blocked_claim`的值从伊文的封锁主张覆盖为玛拉采信后改道的行动。这两件事都有来源，但概念含义被混用，应作为固定状态语义回归，不能因格式和引用合法就判定状态质量良好。
- Planning生成的玛拉profile已包含“需在得知南门封锁后修正计划”和最终北门目标。实际首轮仍按未知信息行动，但提示已提前带入待披露信息，因此不能用这个案例证明严格知识隔离。
- 未到最终报告。路由非每轮激活全部角色是产品真实机制，不人为强迫双人并发来提高测试数字。
