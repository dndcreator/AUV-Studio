## Director是否过度确认

第一轮继续是合理的：玛拉尚未听到并采纳伊文的北门提议。第二轮玛拉说“我同意改道——现在就走”，而伊文第一轮已经说“咱们改走北门吧”。Director仍判“伊文尚未最终明确同意”，因此疑似把自然语言提议和共同计划承诺理解成必须另一次固定格式确认。

不能直接等同“任何提议都是无条件承诺”：若原话是假设、有条件提议、已撤回或任务明确要求二次授权，继续确认可能正确。但本样本没有这些已记录条件，额外确认缺少明显依据。这是语义收敛问题，不是代码每轮固定要求两人重复说“同意”；已有scene_control提示还明确禁止把proposal任务扩大成执行和acknowledgment，但缺少对自然同意的充分判据。

应优先让现有Director引用每个角色的已接受承诺、约束和撤回情况，判断目标是否满足，不强制套话、不替角色作出承诺，也不另加确认Agent。此轮仅定位，未修改生产提示或完成判据。

## State Coder的可靠边界

已有结构约束：来源必须引用此分支的已接受事件；值类型、可见性、私有owner、不可变索引及证据类型受验证；不合法批次不提交；有界修复后仍失败则保留未编码事件。写入标记recorded而非verified，confidence不是独立证明。

证据分类是claim、observation、action、inference及单独授权的player_outcome。它不是一套“LLM已确认世界真相”的证明系统。程序会检查分类枚举和来源是否合法，但不会因此证明“该文本确实属于这个分类”或“此事件语义上足以支持这个值”。

本次先正确记录了伊文的封锁主张为claim，没有直接宣称真实世界已独立证实。随后却把`south_gate_blocked_claim`覆盖成“玛拉采信并改道”，证据类型变成action。新事件引用确实有效，但“南门是否被封锁”和“玛拉是否相信并改变计划”不是同一个命题。即使schema不变，text值仍可以发生语义漂移。

因此不能说当前足够完善或稳定区分世界事实/角色主张。缺口在语义归属及概念稳定性，不只是多加一个fact枚举。应保留两条独立记录：伊文的封锁主张，以及玛拉的路线选择/对该主张的采纳；共享目标的后续变化不能冲掉原主张的归属与未证实状态。已给定背景事实、角色观测、口头陈述和授权世界编辑也应继续区分，不能单凭高confidence升级。
