# 测试计划与覆盖

最后更新：2026-10-29

当前分层执行、退出码、独立Judge与基线规范以 [TESTING.md](TESTING.md) 为准；逐文件保留/合并/改名依据和能力矩阵见 [TEST_AUDIT.md](TEST_AUDIT.md)。以下保留历史功能覆盖明细，不将测试条数作为语义准确率。

## 1. 后端测试分层

1. 引擎层（`backend/tests/test_engine.py`）
- DAG 循环检测
- 条件路由
- 失败重试
- director 与环境注入
- external_agent mock
- human_checkpoint 暂停/恢复

2. API 分支层（`backend/tests/test_human_api.py`）
- 人工干预接口异常分支与队列行为

3. API 面测试（`backend/tests/test_api_surface.py`）
- workflow/template CRUD
- interaction-modes
- memory list/clear

4. API 集成（`backend/tests/test_api_integration.py`；使用捕获队列，不是完整服务生命周期）
- run -> events -> metrics -> report -> compare
- human checkpoint 全流程
- 失败后按节点 retry
- 健康/协议/队列/观测接口

5. 背景书（`backend/tests/test_context_book.py`）
- 旧工作流兼容
- 中文短语触发和单层关联
- 节点私有知识隔离
- Token 预算与优先级
- 真实引擎提示词注入和激活追踪

6. 媒体生成（`backend/tests/test_media.py`）
- 媒体 API Key 不写入 SQLite
- OpenAI-compatible 图片任务与授权头
- OpenAI 异步视频创建和完成刷新
- Generic HTTP Adapter 请求/响应契约
- 外接 Agent URL 与 `task_id` 关联校验

## 2. 前端测试

1. store（`frontend/src/store.test.ts`）
- human_checkpoint 默认配置
- environment 归一化
- interaction 持久化
- context_book、时间和空间字段持久化

2. API client（`frontend/src/api.test.ts`）
- human-response 请求
- memory 请求
- 错误处理
- run 请求默认载荷
- media config、生成和异步刷新请求

## 3. 执行命令

- 后端：`cd backend && pytest -q`
- 前端：`cd frontend && npm run test:run`

## 4. 质量门槛（建议）

1. 新增接口必须包含成功 + 失败分支测试
2. 新增节点至少覆盖引擎执行与 API 场景
3. 关键流程变更必须补 E2E
4. PR 合并前后端测试必须全部通过

## 5. 轻量记忆专项

1. 节点成功后写入 memory 记录
2. 下游节点输入包含 `_memory`
3. 记忆查询与清空 API 正常

## 6. 真实模型 Eval

- 固定场景：`backend/evals/scenarios/roleplay_basic.json`
- 默认仅预检：`cd backend && python -m app.eval_runner --scenario roleplay_basic`
- 显式真实执行：追加 `--execute`
- 可选一次 LLM Judge：追加 `--judge`
- 评测结果：`backend/evals/results/`，不进入 Git
- 普通 `pytest` 只测试评测器逻辑，绝不调用真实模型
- 详细说明：[真实模型效果评测](./EVALUATION_GUIDE.md)

## 7. 动态状态专项

1. 任意领域概念可由 State Coder运行时创建，无需预设字段
2. 缺少未来相关性依据的概念被拒绝
3. 每轮、全局和单实体概念预算生效
4. 私有概念只对所属节点可见，路由和公共事件不可见
5. Director阶段审计同一次调用返回并应用状态 Patch
6. `dynamic_state_updated` 事件包含版本、来源和接受/拒绝结果
7. 声明类型与实际值不匹配时拒绝写入
8. 新概念初值失败时原子撤销 Schema，不残留空概念
9. 私有 owner、visibility、scope 与 value type 不可越权修改
10. Schema/State 操作必须引用本轮准确 action/event
11. round-TTL 状态到期自动退休
12. 连续 Dynamic State 缺少 Director 时工作流校验失败
13. Dynamic State 检查点回滚后精确恢复私有概念、值与来源
14. `dynamic_state_quality` 真实模型场景检查持久事实遗漏、状态膨胀、瞬时心理细节和来源完整性
15. 废弃状态字段会被忽略且不触发迁移或回退读取，规范输出只包含 v2 字段
16. Memory API 与运行召回只接受 `fact|character`，当前状态只来自 Dynamic State
17. 前端从 `runtime_metrics.progress` 和 Dynamic State 构建监测视图

## 10. 固定文风基准

- 验证两次执行只覆盖一份 Markdown，正文不重复保存；素材、写作要求、评分规则与版本变化会使基准失配，不显示跨基准分差。
- 验证 `writing_styles --judge` 预检为三次调用，无 `--execute` 不访问模型。
- 产品报告回归验证用户文风原样传递、不要求最低字数、文学提示词不混入原始 Provider 数据或运行指标。
- 真实文学质量需显式执行 `writing_styles --execute --judge` 后阅读正文；接口生成完整的 100 分仅是协议结果，不是文学质量分。

## 16. 行动一致性接纳回归（2026-10-25）

- 六类固定检查协议；无效 JSON、无效/非标量判断、伪造引用、矛盾 decision/findings 均不得放行。
- 未激活的背景规则和其他实体时代设定仍进入可信检查投影；模型连接密钥不进入。私有依据只能在审计侧使用，修正通知不向行动者回传。
- 真执行器配合假模型覆盖先拒绝后修正、持续冲突、实质性未知、无效响应、超时和预算异常。拒绝候选保留在签名事件中，但不进入后续角色输入、记忆、报告素材或阶段审计；成功事件 parent 指向对应检查事件。
- 内置节点最多两份候选；外接 Agent 只调用一次，不自动重放副作用。检查上下文超限在检查调用前停止，不截断证据。失败保留既有运行状态；正常旧场景测试显式提供假的检查回应，不绕过接纳门。
- Eval 预检包含一致性检查调用，额度不足不能启动真实运行；精简示例文件保留检查统计。前端新事件不改变节点运行状态，不进入 Live/可读过程。
- 这些是零付费工程回归，不把预设 checker 的回应当作真实模型的时空推理或信息边界通过证据。

## 17. 解析恢复与成稿边界（2026-10-25）

- 覆盖 JSON 无效、结构缺失、输出截断、一次修正成功、两次失败、原始请求/预算异常传播，以及未配置模型时不伪造草案。
- 临时错误退避重试，每次物理尝试计入同一预算，失败保守预留；不可恢复 HTTP（含 402）及预算上限不盲目重试。
- 浏览器编译 API 与后端共用逻辑，502 提供 code/message/diagnostics；日志不含私密模型正文，前端保留诊断但只显示可读 message。
- 自然语言场景从空工作流开始，用假模型走真实编译/引擎/写作链路；编译失败也只保存一份精简结果。执行成功但写作调用失败时 Eval 标为 partial 并退出非零。
- 连续报告排除派生 summary 与失败节点输出，DAG 汇总能力保留；文学提示词保留未决事项，默认作品标题不带内部 run_id。
- 真实重测完成模拟，但文学忠实度仍人工判 fail，不能把规则分数当作效果通过。详见 EVALUATION_GUIDE 和最新本地场景记录。
- 最终验证：260 项后端、62 项前端测试、生产构建、Python 编译和空白检查通过；没有把实际作品的语义失败改写成测试通过。

## 18. 文学成稿忠实度门（2026-10-25）

- 产品 story/narrative 与固定写作评测共用“生成、核验、最多一次修正、复核”；briefing 不新增调用。验证通过后才返回作品与来源/候选哈希，持续失败不发布，不改已有行动或运行状态。
- 覆盖格式错误、伪造引文、判断与 findings 不一致、空白/截断/mock 输出、网络错误、预算不足、四次调用计量，以及纠错时拒绝草稿不能进入 source。
