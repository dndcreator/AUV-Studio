# 世界模拟核心架构与验收

确认日期：2026-11-13，北京时间。本文记录用户确认的核心原则，并作为后续实现与评测的约束。不能再用“重要信息摘要”解释State。

## 四类权威与职责

| 机制 | 保存什么 | 不负责什么 |
| --- | --- | --- |
| World Setting / Context Book | 稳定背景、规则、时代空间和初始条件；详细设定按需激活 | 剧情发展和当前属性值 |
| Memory | 节点的经历、知识、主观认知、关系体验和历史；可错误、可不完整 | 宣告客观世界事实 |
| State | 当前实体、属性、关系、持续条件的统一结构化表示 | 对话摘要、重要事件清单或另一个Memory |
| Event Log | 已接纳行动、控制、状态提交和玩家干预，保留因果与来源 | 替代当前State或自动认证行动声称的结果 |

重要程度不决定信息属于哪一类。伊文说“南门封锁”是事件和记忆；南门已确立的通行状态才是State。玛拉听到、相信或表达改道决定不能因此自动成为新状态概念。若模拟确实建模了路线等属性，只有已确立的对应属性变化才更新。状态允许不同粒度，不另建Object/Micro/Macro状态库。

概念定义实体的属性或关系，State是其当前取值。世界概念可随过程发现，不预设领域字段全集；定义的主体、谓词、含义、类型和可见性不能通过换名或覆盖值悄悄重解释。来源标签描述证据性质，既不能单独授权，也不应一刀切决定能否写入。高confidence、有效JSON或合法引用都不等于语义正确。

## 统一State的实现

继续以`dynamic_state`为唯一领域状态。`world_state`仅保留时间/空间坐标，`runtime_metrics`只记录机械执行进度。新`dynamic_state.entities`是同一State内的实体登记，不是平行数据库。

- 实体记录具有`id / kind / name / agent_node_ids / visibility / owner_id / source`。用户初始定义及执行节点初始化该登记；人物可以没有模型节点，多个执行节点也可显式绑定同一实体。
- `entity_summary()`按登记统计实体与类型，不读剧情、不调用模型。群体节点是一项群体实体，不默认等于某个人口数；未明确定义的人口不会被编造。死亡等属性不等于抹去实体历史。
- 新实体通过可选`entity_ops`的`register`提交，需要精确已接纳来源；不得自行创建或绑定执行节点、改变已有实体身份。与同批属性更新共同原子接受/拒绝。
- 属性/关系定义必须具有`subject_id / predicate`。定义description保持稳定；值通过现有`state_ops`更新，不能把“封锁信息”换成“采信后的决定”。
- 新增`value_type=entity_ref`表达单目标关系，目标必须已登记或为null。不能通过公开关系或公开属性暴露私有实体；其他类型仍为scalar/text/list/object。
- 运行时继续检查类型、owner、引用、权限、保留策略和提交条件。语义抽取仍由模型承担，不能通过上述结构约束声称彻底解决语义漂移。

初始无Agent实体示例（不是固定领域字段）：

```json
{"simulation":{"dynamic_state":{"enabled":true,"entities":{
  "quiet_npc":{"kind":"individual","name":"没有执行节点的人物"},
  "guild":{"kind":"organization","name":"公会"}
}}}}
```

## 分支记忆与持久化

仍使用SQLite的`memories`表。新建运行不因为复用Workflow就继承旧运行记忆。恢复/分支只读取自身与祖先历史，并按各分支存档事件序号截断；先筛边界，再取召回窗口，不让父分支未来内容挤掉合法旧记忆。兄弟分支不能互相读取后续记忆。

分支父指针与截止点固定在运行定义记录内，不能因为同run人类回复覆盖了input而丢失。角色可见性继续按节点筛选，State与Memory允许互相不同；同一事实的不同认知不被强行合并。

持久化历史与召回窗口不是一回事：SQLite保留历史，运行上下文最近100条，再按节点筛选供模型使用。退出后读取同一边界沿用相同窗口规则，不宣称每轮把全部历史都喂给模型。

## 存档、恢复与安全执行边界

复用Run、Event Log和检查点；新增`run_definitions`只存每次运行固定的Workflow/World Setting版本与分支元数据，不存另一个世界State。SQLite启动的`Base.metadata.create_all`创建该新表，无需修改既有表列。配置快照与项目定义同属本地敏感数据，可能含自定义端点配置；不通过新增世界读取API公开配置或凭据。

检查点增加定义hash、Director guidance和未完成参与者列表。已接纳行动及其记忆写入后产生`execution_checkpoint`。恢复重用保存的调度边界，跳过已完成参与者，不重新调用模型生成已经确立的历史；没有剩余参与者时进入审计，而不是激活任意角色补齐。

读取时校验存档事件链与固定定义hash。修改编辑器中的Workflow不会改变旧存档；同run的人类继续不创建自指父分支。显式“修改配置后重试”保留原有修复能力，但它是新配置分支，不是透明读取旧世界。

暂停请求在现有安全边界完成，不宣称立即中断每个供应商请求。进程退出后沿用现有中断恢复逻辑，将未完成任务标记失败；不自动重发未知外部副作用。恢复发现外部调用结果不明、未闭合的已接纳行动或半批提交时返回409，要求明确回滚/核对，而不是偷偷重放。

旧运行如果没有固定的定义快照，不会用当前项目冒充旧世界；自动恢复会明确拒绝。历史记录不被静默重分类或删除。本轮没有对旧数据进行猜测式迁移。

存档当前为数据库内运行实例，不是独立导出的可搬迁游戏存档包；恢复创建可追溯的子运行/分支，保留原历史。完成原目标或耗尽原轮次后，不会自动生成新的任务/重置预算。

## 职责边界

- Planning规划必要概念维度、背景和可观察目标，不预写完整本体、剧情结果或每条记忆。角色profile不再机械复制全局未来目标。
- Director管理情境、节奏、阶段和完成条件，按自然语言承诺及条件判断，不要求重复套话，也不替Actor同意。现有联合审计检查状态提案的定义与来源，不是独立语义证明。
- State Coder把已确立变化编码为统一State操作；不能借编码创造世界事实。概念扩展必须遵守定义与证据边界。
- Router只选择参与者，不设定事实、编写具体行为或另行裁定任务完成。
- Runtime检查结构、来源、权限、关系引用及原子提交。普通变化不新增Director模型调用；本轮没有实现“Director自由创建并直接生效的外部事件”或独立重大规则审批队列，不能把提示中的审阅职责冒充这些能力。

## API

| 接口 | 行为 |
| --- | --- |
| `POST /api/runs/{id}/pause` | 复用安全停止请求，等待status变成stopped后读取 |
| `GET /api/runs/{id}/world-state` | 返回最近完整检查点的State、实体统计、checkpoint_seq和Workflow版本；是本地操作者视图，可含私有状态，不是外接Agent知识接口 |
| `POST /api/runs/{id}/resume` | 验证边界后复用rollback队列创建子运行，返回RollbackResponse |
| `GET /api/runs/{id}/checkpoints` | 包括新的execution_checkpoint |
| `POST /api/runs/{id}/rollback` | 显式选择存档点创建分支，恢复固定设定 |

接口默认不启动模型；resume/rollback入队后会像正常运行一样产生模型调用，预算仍由调用者/运行机制管理。本轮没有增加新的前端按钮或说明文字，既有检查点入口可见新类型。

## 验收矩阵与限制

| 用户原则 | 确定性验证 |
| --- | --- |
| 从State查询实体数量、区分群体与人物/非Agent人物 | `test_entities_include_nonagents_and_groups_are_not_population_counts` |
| 概念含义与主体/谓词稳定；同一属性可以换值 | `test_concept_meaning_cannot_be_rewritten_even_by_reactivating_an_old_id`、`test_same_proposition_can_change_value_without_rewriting_schema` |
| 来源有效、隐私及关系引用不越权 | 新实体原子提交测试、私有目标/悬空引用测试及既有private-owner/knowledge边界测试 |
| 退出会话后读取并继续，不重演已接纳行动 | SQLite关闭/重开会话、暂停、固定版本恢复的真实Engine测试 |
| 分支后续状态与记忆独立 | root/left/right/grandchild/fresh记忆测试、同存档双分支运行测试 |
| 状态、事件与设定保持一致 | 来源引用、事件链、定义hash篡改拒绝及既有rollback/恢复测试 |

这些测试使用真实数据库、API/Engine及确定性模型替身，不是实际LLM语义质量成绩。本轮不调用真实模型。同步修订State Coder Gold Cases/Judge标准：不再奖励把承诺、请求等重要记忆抄成State；保留待人工校准状态，变更后的case fingerprint使旧基线不再直接可比。

2026-11-13最终完整门禁：后端601项（unit375 / integration223 / system3）通过，35.52秒；前端87项通过，生产构建通过。退役定义约束补充后先跑70项定向回归，再完成上述全量门禁。没有调用真实模型或把历史试验重新标成新架构质量通过。

尚不保证模型永不把话语误判成世界变化，也不声称重大规则语义争议已获得独立审核。后续真实测试应专门检验这些反例，而不是以测试数量或“全部通过”替代语义验收。
