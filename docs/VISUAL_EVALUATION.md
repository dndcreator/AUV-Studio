# Visual Director 真实测试记录

时间：2026-11-01，北京时间。仅一次受限测试活动，不是稳定性基线。

## 执行方法

使用 `app.behavior_eval --suite visual`，调用实际 `generate_visual` 产品函数。
两个固定任务：地牢求生、太空船故障。共享原评测预算、超时、请求追踪和结果分级。
未配置独立 Judge，没有自动复用目标模型 Key；语义状态保持 not_evaluated，由工程人工检查。
这两个案例及新增Judge校准正反例都保持 pending_human，不冒充已审核Gold。

授权上限：6次请求、30000 Token、估算USD0.10。实际累计6次，10031输入+4758输出Token，
估算USD0.029063（沿用输入1/M、输出4/M的评测估价，不是服务商账单）。没有继续追加调用。

## 发现与修复

| 请求 | 结果 | 定位 |
| --- | --- | --- |
| 1 | 截断，拒绝应用 | 视觉排版任务使用thinking且输出不够紧凑 |
| 2–3 | 配色/映射协议不匹配，拒绝应用 | theme原本是任意字典，Schema没有固定字段；绑定键值含义不清 |
| 4 | 合法SVG竖线被拒绝 | width=0对竖线合法，原验证器错误地要求所有尺寸大于0 |
| 5–6 | 两个场景均返回有效结构 | 共3617输入+920输出Token，估算USD0.007297 |

修复：仅官方支持的DeepSeek视觉请求使用关闭thinking的局部副本，不影响Actor/Checker/Director；
限定预览规模、严格Palette模型、明确值到区域ID/颜色的映射，合法水平/竖直线与退化图形分开校验。
增加安全错误码及有界目标文本诊断。修复没有放开私有状态、不接收任意SVG、不无限重试。

## 输出检查

- 地牢：暗褐背景、灰褐石墙、橙色火把，入口/深室；8个通用图元。
- 飞船：蓝黑背景、冷蓝舱室与管线、控制台、红色灯，舰桥/工程舱；7个通用图元。
- 两套计划在配色和装饰结构上不同，不只是改名；仍是简陋示意图，不能称为成熟美术或完整飞船。
- 两套计划都生成了公共位置及警报绑定，没有创建人物死亡或行动结局。

## 动态投影检查

`node scripts/verify_visual_result.mjs` 将真实生成的方案交给实际前端 `buildSceneFrame`，
使用合成的“行动已接受→状态已提交”事件作为控制输入，不再花模型Token。
这不是又跑了一轮真实自主模拟，也没有测试State Coder自行发现位置概念的能力。

| 检查 | 地牢 | 飞船 |
| --- | --- | --- |
| 移动到指定区域 | 通过 | 通过 |
| 状态绑定正确应用颜色 | 通过 | 通过 |
| 颜色相对初始值可见改变 | 通过 | 未验证：初始已红色，只有on映射 |
| 未提交更新不影响展示 | 通过 | 通过 |
| 缺少行动来源不影响展示 | 通过 | 通过 |
| 私有位置不影响展示 | 通过 | 通过 |
| 回放恢复初始展示 | 通过 | 通过 |

飞船的灯光开关还没有闭环：需要明确off/on两种状态映射，不能把同一红色重复应用称为变化。
只有单次有效输出，不能据此认证模型稳定性、跨主题泛化或视觉审美质量。
