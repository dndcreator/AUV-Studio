# 玩家干预网关

更新时间：2026-11-06，北京时间。

## 当前范围

已接通 Outcome、Action、临时角色接管、交接、干预历史、回滚/分支与已有场景绑定。不重写执行引擎，不增加状态数据库或另一套语义写入器。

- 原导演指导入口保留：调整方向，不保证指定结果发生。
- 新增“指定结果”：自然语言交给现有 State Coder 契约解析，通过验证后成为当前世界事实。
- Action 让指定角色尝试行动，不能指定成功；自主角色可以按自身意愿拒绝。玩家接管后由玩家提供行动意图，模型只负责按该角色的上下文表达尝试，仍经过同一 Action Check。
- 适用于各种连续模拟模式，不按剧情、研究或某个领域硬编码死亡、位置等状态字段。

## 使用与接口

运行中的连续模拟，在底部输入框选择“导演指导 / 尝试行动 / 指定结果”，输入指令并发送。行动模式选择角色；“接管 / 归还控制”管理临时控制权。高级版本字段不出现在 UI；前端提交前读取当前版本。排队、生效、冲突和失败是不同的状态，不把 HTTP 202 当作世界已经变化。Action 的“已记录”只表示贡献通过检查，不表示尝试达成目标。

`GET /api/runs/{run_id}/interventions` 返回：

```json
{
  "run_id": "run_xxx",
  "state_version": 2,
  "enabled": true,
  "accepts_outcomes": true,
  "accepts_actions": true,
  "pending_request_id": null,
  "controls": {"wang": "player_controlled"},
  "handoffs": {},
  "waiting_actor_ids": ["wang"]
}
```

不会返回私有世界状态。仅 `running` 的 continuous workflow 接受行动与控制；Outcome 还要求 Dynamic State 已启用。

`POST /api/runs/{run_id}/interventions`：

```json
{
  "mode": "outcome",
  "instruction": "老王杀死老李，无人目击。",
  "actor_id": "wang",
  "base_state_version": 2,
  "request_id": "client_unique_id"
}
```

Outcome 的 `actor_id` 可省略；Action 必填，必须引用模拟实体，不授予角色接管权。Action 使用 `mode=action`，自然语言仍是 `instruction`。`request_id` 可由服务端生成，客户端提供时用于幂等：同 ID 同内容不重复排队，同 ID 不同内容返回 409。前端重试同一未确认请求时复用 ID。一次运行最多一个待处理行动或结果请求。

可选 `conflict_policy=overwrite` 仅用于 Outcome：用户在历史窗口明确确认后，允许替换冲突的当前值，不允许改历史、修改不可变字段或绕过类型/隐私校验。它不是强制通过任意非法补丁的开关。

202 返回 `request_id / request_seq / status=queued`。通过运行的原事件接口轮询完成情况。未知运行返回 404；版本过期、重复内容冲突、非运行状态、已有待处理请求、控制权交接中返回 409；非法模式、空文本、未知角色等返回 422。

`POST /api/runs/{run_id}/controls` 接受 `actor_id`、`control=player_controlled|autonomous` 和幂等 `request_id`，返回 202。`handoff` 是服务端推导的交接状态，不能由客户端直接设为已接管。每个角色最多一个待交接请求。

`GET /api/runs/{run_id}/interventions/history?limit=30&before_seq=...` 返回 `items / next_before_seq`，包含请求类型、角色、自然语言、状态、安全错误码、追溯事件以及前后检查点。窗口支持追溯、干预前分支、从应用后继续和显式覆盖当前事实；翻页不重复加载全部日志。

## Action 与控制权

Action 作为目标角色的一次优先参与请求接入原调度，不允许直接提交状态补丁。自主模式通过原 Agent/外接 Agent 运行，保留角色意愿；接管模式跳过原自主生成器和外接 Agent 的调用，用平台模型将玩家意图表达为正常行动 JSON。Action Check 同时检查世界规则、信息边界、所有权和玩家意图，不能将请求当作结果证据。格式/检查/供应商失败拒绝该请求，不污染事实或 Memory，也不因此终止整个模拟；不自动替玩家另作决定。

接管和归还在安全行动边界提交。已在执行的行动先完成，再发 `player_control_changed`，不会同时产生两位控制者。接管角色被激活后若没有输入，发 `player_waiting` 并异步等待；等待不生成空行动、不推进轮数、不调用 Actor/Router/Director。停止和归还控制可打断等待；归还后原 Agent 使用最新状态和记忆继续。其他已选中的自主角色优先执行，避免被等待中的角色挡住。同一运行的队列 Worker 会保留到等待结束，这是本地交互任务的占用，不代表新增模型并发。

控制权保存在事件派生的机械运行上下文和检查点中，不放入 Dynamic State 或角色永久定义。回滚恢复当时已完成交接的控制权，不复制之后或尚未消费的请求。

## 执行与事务

1. `player_requested` 只记录请求，不是事实。请求不会加入 `simulation_actions`，也不会作为导演全局指导广播给角色。
2. 引擎在行动之间的边界消费请求，不与正在等待模型的角色抢写。已发起的角色行动不会被强行撤销；它先结束，然后再处理请求。
3. 核对 `base_state_version`。若有尚未编码的旧行动，先走原 State Coder 编码；如果因此改变状态版本，拒绝过期请求，要求用户确认后重发，不能偷偷覆盖。
4. 使用原 State Coder 的动态概念、类型、预算、保留策略和不可变 owner/visibility/index 契约解析结果。自然语言的领域意义仍由模型判断。
5. 校验实体引用和状态批次。格式或补丁失败最多修复一次，不能部分提交。语义冲突不会交给 Director 按剧情喜好否决，也不自动改历史。
6. 单一数据库事务内写入 `player_outcome`、完整的 Dynamic State 检查点以及 `player_applied`。成功提交后才发布到引擎上下文。停止或写入失败时不发布事实。
7. 失败写 `player_rejected` 和安全错误码，不输出供应商原文。运行结束及重启恢复时取消仍未处理的请求与交接。

不使用伪造的 `node_id/action_index`。结果状态的证据为：

```json
{
  "evidence_kind": "player_outcome",
  "source_refs": [{"event_type": "player_outcome", "event_seq": 123}]
}
```

只有网关内部的授权提交可以使用这种来源；正常 Actor 输出不能自行获得这个权限，也不推进正常行动的 State Coder 游标。事件签名根据当前真实链头生成，避免 API 请求在模型等待期间到达时造成审计链分叉。事务写锁仅适用于本地单运行时，不是跨进程调度方案；禁止跨 `await` 持有该锁。

## 信息、报告与回滚

- 私有事实按现有 owner 过滤；模型可以给指定合法角色写入私有知识，但不能更改既有概念的 owner、visibility、类型或索引。秘密内容不得编码为全局描述或全局值。
- 不把原始结果指令复制到所有角色的近期行动、Memory 或全局指导里。角色继续从过滤后的 Dynamic State 继承事实；不新增第二份当前状态。
- Director/Checker 可依照既有审计权限看状态，但不得通过指导、场景契约泄漏私有内容。此点需要真实模型评测，不能仅凭提示词或离线测试宣称完全可靠。
- Full Log/Trace 保留请求、提交和失败证据。面向本地用户的最终总结/报告补充当前仍有效的玩家事实和知识边界；这份全知视角素材不能用于角色间广播。它不替代完整事件历史。
- 路由激活时保存轮次前检查点，因此第一轮干预之前也可以回退。每次真正处理行动、结果和交接前另存 `player_checkpoint`，保留此前已完成的其他角色行动，不粗暴退回整个轮次。Outcome、Action 接受和控制权应用均有完整应用后检查点；原 rollback API 创建分支，恢复私有状态、控制权与行动游标，不重放后来的干预。
- 分支启动时核对原工作流、数据库中的原检查点和原审计链，拒绝被修改的快照。发布 `state_restored` 作为经过验证的公有基线，附原事件哈希和来源。场景可继承原分支的公有绑定值，Full Scene 和报告可看到继承的公开行动；这些不是新执行的事件，不重复自动播报。恢复用的私有快照与人工恢复信封不会通过 `input` 传给角色或外接 Agent。
- 场景只投影已有 public binding，要求真实行动/结果来源，或与验证后的继承基线完全一致。私有状态不驱动画面；角色卡显示玩家控制/交接/等待状态。新的领域概念如果没有绑定，仍需使用现有“生成视觉场景”入口更新映射；不偷偷增加模型调用，也不声称任意未知事实都能自动变成图像或重绘世界。

## 成本与验证

空队列不调用模型。结果解析最多两次逻辑请求，每次输出上限 2400 Token、45 秒；供应商原有的有界传输重试仍可能增加物理请求次数。有旧行动需要编码时，另有一次编码请求及最多一次原有修复；初次编码和修复批次分别受 45 秒期限约束。上下文超过 90000 字符拒绝，不静默裁剪。这里不是固定美元预算承诺。

新增离线测试使用真实 FastAPI、SQLite、事件提交、执行引擎、权限投影和 rollback 分支，仅模型响应为确定性替身。覆盖秘密结果、类型/实体/可见性错误、不可变 owner、假来源、截断、模型失败、并发停止、写入中断、幂等、版本冲突和最终素材继承。前端覆盖结果与导演指导分流、排队不等于生效、公有来源投影及私有/缺失来源反例。

尚未运行本轮付费模型；不能据此声称自然语言解析已经稳定理解“无人目击”，或者模型永远不会将秘密误编码为公开事实。后续真实测试需单独批准预算。框架功能闭环不等于真实模型行为质量已经经过充分验证。
