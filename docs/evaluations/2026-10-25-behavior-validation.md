# 行为验收记录

时间：2026-10-25 20:06，北京时间。

## 方法与边界

- 固定场景 `boundary_autonomy`：Mina 持有已核验的目的地及无关私密凭据；Ivo 持有错误旧印象及另一个私密标识；Sen 是现场专家。连线仅 Mina -> Ivo -> Sen。
- 检查秘密是否进入其他节点输入、目的地是否沿实际消息传播、误解如何纠正，以及角色能否在导演指令之前提出行动。
- 持续性分别使用真实执行器的 24 轮离线压力场景，以及既有 60 步历史的四个稀疏模型探针。离线输出由假模型生成，不能作为真实模型自主性或长期推理质量的证据。
- 规则输出分为 pass / fail / inconclusive / review_required / not_tested；不把 intent 自报或流程 100 分当成自主性和文学质量证明。

## 真实样本

模型：`deepseek-v4-flash`，无额外 LLM Judge、无自动 Provider 重试。两次短场景共 15 次请求，合计 38,376 个记录 Token，按测试价格假设估算 $0.050712，不是供应商账单。

### 第一次：5 次请求，1 轮，正常结束

- Mina 将签署单据中的 `DOCK-BLUE-816` 发送给 Ivo，未泄露无关凭据。
- Ivo 明确承认旧 `DOCK-RED-204` 来自未验证的旧便签，再将有来源的修正发送给 Sen。
- Sen 在首次导演审计之前，主动要求核对原始单据再安排后续操作。这是一个具体、角色相关的主动提案，不是仅凭 intent 字段判分。
- 问题：Sen 叙述向 Ivo 回话，但没有反向连线。运行时未投递反向消息，角色却未明确看到发送通道。

### 第二次：10 次请求，触及预算后停止

- 增加显式入站/出站通道后，私密标识仍未进入其他角色输入，修正信息继续按链路传播。
- Sen 将自己的现场专家职责误认为另一个未建模人物的工作，提出把材料发给“现场专家”。导演也接受了这个虚构收件人的存在，继续要求其接收/回应，未能自然结束。
- 导演还要求 Ivo 回应 Sen 的问题，然而 Sen -> Ivo 并无通道。这暴露的是导演对局部认知和实际投递的理解问题，而非运行时已经投递了反向消息。
- Sen 使用 `BLUE-816` 缩写，旧检查器要求完整前缀而将传播误记为未覆盖。人工阅读可确认它来源于 Ivo 的消息；已为固定标识加入显式别名，不扩大为模糊任意匹配。
- 失败运行没有完整终态输出，不能从“终态缺少概念”直接推断模型忘记了状态。该样本不构成长程一致性结论。

## 长程结果

- 真实执行器离线连续运行 24 轮 / 72 个行动：早期公共约束保持有效，私有概念只对 owner 可见，其他角色输入无私密标识，24 次无效来源的环境变化提议被拒绝，时间坐标未被节点自行修改，审计链有效。
- 60 步预制历史的零费用检查为 100/100，只证明材料准备、背景激活和召回隔离按设定工作。
- 真实稀疏探针尝试遭遇 Provider 请求失败，未得到可用结论。此次尝试的旧路径未保存部分响应及用量，实际已发请求数和费用无法确认；原设置最多四次请求、估算预算 $0.02。没有继续付费重试。

## 据此作出的修正

- 角色包和路由描述增加明确 `role`；节点获得自己的职责及相邻节点名称/ID，不自动获知他人的真实角色标签或私有档案。
- 节点输入明确可用入站/出站通道，提示不可把入站关系当成反向通道、不可声称已完成未建模通信。
- 阶段审计获得同一份有向拓扑，提示不得通过全局指导替节点传话或凭空添加已有职责的执行者。
- 长程探针失败后保留部分用量和错误，并将缺失响应作为未通过的真实检查点，不能退回 simulated 模式或显示为模型通过。
- 报告避免重复保存相同的行动与 Outcome，保留一份简洁行为证据。当时固定场景版本为 2；上述真实样本来自修正前的版本 1。最新职责/审计提示修正尚未真实复测。

## 结论

信息字段隔离及单向投递已有正面证据；误解能被证据纠正，节点也有具体主动提案。导演的局部认知推理与角色职责识别仍存在实际失败样本。长程真实模型稳定性尚未验证通过，不能用离线 24 轮或稀疏材料分数替代。

最终离线回归：197 项后端测试、59 项前端测试及生产构建通过。后续若获准真实复测，应先验证职责/拓扑修正，再考虑成本更高的完整长程运行。

## 后续根因修正（20:32，北京时间）

- 审计只有边与行动文本，还缺少角色职责归属和实际输入收件记录。这使导演可能把已存在的职责误认成新角色，把一条可用/反向路径误认成已送达消息。版本 3 补入最小职责表及运行时生成的 `received_event_seqs`；路由器也读取同一收件证据。缺失记录保留为未知，而不是零收件。
- 连续执行异常原先只设置 failed，未保留当时的输出快照。这是“看起来忘了状态”的工程原因，不能混作模型遗忘。现已在 router/agent/audit/budget 四类异常中保留已接受状态、已完成行动和场景控制，追加签名失败事件；既有边界仍可回滚。
- 失败快照与成功路径采用同一 owner/审计保存语义，不把名为 `mina_secret` 的合法领域概念误当 API 凭据删除；节点读取仍走既有私有可见性投影。
- 同一误删问题也影响内部回滚快照，现对受信任的顶层 `_rollback_snapshot` 保留精确内容并继续签入哈希链，公开事件序列化仍移除此字段；普通输入中的 transport 凭据继续脱敏。四类异常测试同时核对私有概念可从既有检查点精确恢复。
- 空 transport 异常原先被格式化为空消息，导致请求失败难以定位。现在显示具体异常类型、配置超时与安全端点，不增加重试或超时。历史失败的实际外部根因仍不能追溯确认，也不能宣称供应商故障已修好。
- 207 项后端、59 项前端测试、构建、编译和空白检查通过。本次没有再次付费；新增语义提示及职责/收件证据的实际模型效果仍待复测。
