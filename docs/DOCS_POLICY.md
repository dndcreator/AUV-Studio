# 文档维护机制

最后更新：2026-04-09

## 1. 更新原则

1. 代码变更与文档变更同 PR 提交
2. 接口、协议、状态机变更必须同步文档
3. 不允许“代码已变，文档待补”长期存在

## 2. 触发条件

发生以下任一变更时必须更新 docs：

1. 新增/删除 API
2. 节点类型或节点字段变更
3. 运行状态或事件协议变更
4. 测试命令或测试覆盖策略变更
5. 部署方式或环境变量变更

## 3. 最小更新清单

每次功能迭代至少检查：

1. `docs/API_REFERENCE.md`
2. `docs/NODE_SPEC.md`
3. `docs/ARCHITECTURE.md`
4. `docs/TEST_PLAN.md`
5. `docs/CHANGELOG.md`

## 4. 版本与日期规范

1. 文档顶部维护“最后更新”日期
2. 关键协议必须含版本号（如 v1.0）
3. 破坏性变更在 CHANGELOG 明确标注
