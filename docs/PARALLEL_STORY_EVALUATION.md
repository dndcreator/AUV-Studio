# 双并行故事语义对照

## 2026-11-11 实验设计

用户批准一次真实实验：两组各4轮、两个角色，合计最多40次物理请求、16万Token、估算USD0.30、480秒。保留已保存的Thinking配置，单次输出上限2400，28次普通请求之外只允许已有的有界Checker协议修复。无独立模型Judge、小说改写、自动续跑或生产调度变更。

场景是西方奇幻城堡逃脱。Mara持唯一钥匙，Iven知道机关并持有密信；两人都想逃脱，但对政治风险与保留证据的优先级不同。公开场景不向Mara泄露密信具体内容。角色自主决定是否披露、如何交接和协商，不强制成功或预写台词。

- `parallel_propose`：同轮快照并行提案，Checker按a、b顺序检查，可看到已接纳前缀。
- `parallel_batch`：同轮快照并行提案，联合Checker检查整批及相互兼容性，之后才提交接纳事件。
- 两组Actor均不能把同轮另一候选当作已经听到的话。只有此前已接纳行动进入下一轮；自己的历史包含私有字段，其他角色只收到公开投影。

这是复用真实Actor、Checker、信息投影和SQLite事件提交的隔离对照，不是完整生产模拟。没有Director、State Coder、世界事实迁移、长期记忆检索或自适应路由；后续轮次依靠角色设定和可见行动历史。不得把角色声称完成的效果当作独立验证的世界状态。

## 预先确定的人工评阅标准

对照accepted行动、未接纳候选、检查理由和收到的事件引用。每项使用“符合 / 部分符合 / 不符合 / 未验证”，不把Actor或Checker自评当作成绩。

| 维度 | 检查依据 |
| --- | --- |
| 信息边界 | 密信具体内容是否在公开披露前被Mara获知；是否回答本轮尚未收到的话 |
| 行动所有权 | 是否替对方作出回答、同意、移动或选择；请求是否被写成已完成 |
| 因果与资源 | 唯一钥匙、上锁舱口、双人机关是否出现无依据的成功、复制、逆序或相互冲突 |
| 互动与收敛 | 后续行动是否回应已有消息、形成合作或有意义的拒绝，还是重复协商；窗口结束不强制结局 |
| 可读性与人物差异 | 具体台词/动作是否清楚、人物动机是否可辨、细节是否推动互动；不单凭字数和文学修饰评优 |

单样本固定顺序，未控制服务端随机性、缓存和热身；一组若失败或预算中断，不作同等任务速度比较。格式通过和接纳数量相等都不证明语义质量等价。原始紧凑记录单独保存为`backend/data/parallel_story_latest.json`，不覆盖此前控制台速度实验。

本次不是两个完成故事，不能判断哪种并行语义质量更好或更快。下一步应先独立验证受限输出下Checker的Thinking策略和Actor协议稳定性，而不是据此删除Checker、改生产调度或继续堆模型调用。

已接纳公开原文可直接阅读`backend/data/parallel_story_readable.md`；完整事件引用、判断与请求元数据在`backend/data/parallel_story_latest.json`。没有额外小说润色，也没有独立模型打分。

## 显式关闭Thinking的对照

2026-11-11再次获得同一40次请求/16万Token/估算USD0.30/480秒上限授权，执行以下命令一次，不自动追加：

```powershell
..\.venv\Scripts\python.exe -m app.evaluation.parallel_trial --case castle --thinking-mode disabled --execute
```

两种并行方案都发送`thinking.type=disabled`，不再同时发送`reasoning_effort=low`；仅修改本次Provider对象，不写回保存的设置或改变生产Checker默认值。原生Ollama关闭协议未实现，实验会明确拒绝该组合而非伪称已关闭。

原来的Actor失败未保存具体字段，因此无法确认当时是JSON语法还是字段类型问题。本次继续严格校验，不强制转换类型、不额外重生成Actor；通用行动提示增加最小合法JSON格式示例、文本字段类型、可省略字段及转义要求。示例明确不要求角色选择等待，不更改角色自治或行为内容。

两组使用同样的强化提示，因此可作本次组间观察；和上次相比同时改变了Thinking及格式提示，又是单样本固定顺序，不能把所有质量/耗时差异单独归因于关闭Thinking。原始结果另存`backend/data/parallel_story_nonthinking_latest.json`，不覆盖Thinking开启时的失败证据。

人工评阅，不采信Checker自评为最终成绩：

| 维度 | 顺序检查 | 联合检查 |
| --- | --- | --- |
| 信息隔离 | 未见密信核心秘密提前泄露；没有同轮强制回复证据 | 未见密信核心秘密提前泄露；尚不足验证所有认知边界 |
| 所有权 | 没有明显替他人写动作或答复 | 没有明显替他人写动作或答复 |

| 主动性/推进 | 主动提出协作，但多轮反复确认，锁卡住后继续拖延 | 信任冲突和行动更鲜明，但反复推迟操作；两组均未逃脱 |
| 文学可读性 | 有具体对白和动作，第一/第三人称混杂，机械协商较多 | 戏剧张力稍强，同样人称不统一，尚非完整文学成稿 |

联合组第三轮的uncertain理由把玛拉本轮开锁与伊文仍要求插钥匙视为时序问题。然而伊文在轮初尚未收到玛拉这条新行动，不能要求他事后知晓；仅提出尚未更新的请求本身也不等于不兼容的世界结果。这是疑似同轮事后视角误判，不证明联合Checker语义更准。该候选的“放手你就转”另有机关协调问题，需与错误的时序理由分开评阅，不能用一个潜在问题替另一个错误理由背书。

结论：本轮输出稳定性达到观察目标，格式强化后16个Actor响应均合法，但不能追认旧失败字段或承诺长期稳定。Batch没有显示全面质量优势，也不能因这一次疑似误判宣布其不可用。双方都有协调停滞；本微基准未接Director/State Coder，不能据此断言完整产品的节奏控制无效。生产默认值、校验严格程度和调度保持不变。
